# telegram-stories-stat

[English](README.md) · **Русский**

![telegram-stories-stat](docs/cover.jpg)

**Кто смотрел ваши сторис в Telegram, когда — и что с этим делать.** Скилл для персональных ИИ-агентов:
в первую очередь для [Hermes Agent](https://github.com/NousResearch/hermes-agent), но подойдёт любой агент,
который умеет запускать команды.

Небольшой фоновый сервис собирает каждого зрителя ваших сторис с точным временем и сохраняет всю историю,
которую Telegram ещё хранит. Агент отвечает готовыми таблицами: по одной сторис, за любой период, по ядру
аудитории, по лучшему часу для публикации. По желанию сервис пишет зрителям в личку по правилам. По
умолчанию — только контактам, с жёсткими лимитами и стоп-краном.

В сервисе нет нейросети. Агент только читает таблицы, которые тот печатает.

```
Сторис 221 · 05.10.2026 14:01 · 📷 фото
👁 133 · ❤ 7 · 💬 2 · ↪ 0 · к обычному +12%
1ч: 41 · 6ч: 88 · 24ч: 121 · 48ч: 133 · новых зрителей: 3
👥 101 · 📇 4 · · 28 · ⭐ 6
```

| № | Время | Через | Имя | Ник | Реакция | Кто |
|---:|---|---:|---|---|:---:|:---:|
| 1 | 14:03 | +2м | Катя Смирнова | [@kate](https://t.me/kate) | ❤ | ⭐👥 |
| 2 | 14:10 | +9м | Алексей | — | | 📇 |
| 3 | 15:22 | +1ч21м | Макс Ли | [@maxlee](https://t.me/maxlee) | 🔥 | · |

*(Строки выдуманы. В Telegram это приходит родной таблицей, ники кликабельны.)*

## Быстрый старт

```bash
# 1. поставить скилл (Hermes)
hermes skills install itpartypattaya/telegram-stories-stat/skills/telegram-stories
# 2. одна команда в терминале: зависимости, база, конфиг, вход по QR, сервис, импорт истории
python3 ~/.hermes/skills/telegram-stories/scripts/install.py
```

Второй шаг сам ставит Telethon и `qrcode`, если их нет, создаёт базу и конфиг и **рисует QR-код прямо в
терминале**. На телефоне откройте Telegram → Настройки → Устройства → «Подключить устройство» и
отсканируйте его. Если включена двухфакторная защита, установщик попросит облачный пароль, символы при вводе
не отображаются. Дальше сервис запускается, а установщик предлагает загрузить все прошлые сторис.

Код входа никуда приходить не должен. На живом аккаунте Telegram дважды ответил «код отправлен в
приложение», и код так и не пришёл — поэтому вход по QR и стал способом по умолчанию. Вход по номеру и коду
никуда не делся: `stories.py login --with-code`.

Если ставите как плагин (`hermes plugins install itpartypattaya/telegram-stories-stat`), скрипты лежат в
`~/.hermes/plugins/telegram-stories-stat/skills/telegram-stories/scripts/` — подставьте этот путь. Сервис
запускается из той копии, в которой отработал `install.py`. С любым другим агентом: склонируйте репозиторий
куда угодно, запустите те же скрипты и покажите агенту `SKILL.md`.

Один раз понадобятся ключи Telegram API (`api_id`, `api_hash` на <https://my.telegram.org> → API
development tools). Установщик спросит их при входе и сохранит в `~/.hermes/.env`. Если там уже есть
`TG_API_ID`/`TG_API_HASH`, ничего не спросит. Дальше просто спрашивайте агента: *«кто смотрел последнюю
сторис?»*, *«сводка по сторис за сентябрь»*, *«кто моё ядро?»*.

Проверить, что всё в порядке: `install.py --check`.

## Как это работает

![Архитектура: один сервис между Telegram и базой SQLite, агент читает её через CLI](docs/architecture.ru.png)

Один фоновый процесс (`daemon.py`) общается с Telegram через свою сессию и пишет всё в SQLite. За
статистикой агент в Telegram не ходит: он запускает `stories.py`, тот читает базу и печатает таблицы.
Уведомления уходят через бота вашего агента родными таблицами.

![Жизнь сторис: счётчики раз в минуту, список зрителей при росте, пульс через 2 часа, дайджест](docs/story-life.ru.png)

- События «кто-то посмотрел сторис» в Telegram нет, поэтому сервис опрашивает сам. Раз в минуту один запрос
  возвращает счётчики всех активных сторис. Список зрителей читается, только когда счётчик вырос, —
  от самого свежего зрителя до первого, который уже есть в базе. Новые сторис проверяются раз в 5 минут.
  Сторис, закреплённые в профиле, — раз в 30 минут: они продолжают набирать просмотры и после 48 часов.
- Импорт истории проходит по архиву сторис и читает все списки, которые Telegram ещё отдаёт. На живом
  аккаунте: 209 сторис с июля 2023 года, списки зрителей есть с конца августа 2023-го, 30 110 просмотров,
  861 секунда с паузой по умолчанию 2 секунды.

### Процессы и ресурсы

| | |
|---|---|
| Постоянных процессов | **1** (`telegram-stories.service`, systemd-сервис пользователя) |
| Память | **~65–70 МБ** (замер на живом сервисе: 67,8 МБ RSS, 53 МБ в его cgroup; Python 3.11 + Telethon 1.44) |
| Процессор | около 0,5 с на запуск, дальше ~3 мс на запрос к Telegram — порядка 0,1 % одного ядра |
| Сеть | 1 TCP-соединение с Telegram, несколько КБ в минуту |
| Диск | база ~5 МБ на 30 000 просмотров; миниатюры ~20 КБ на сторис (можно отключить) |
| Вызовов нейросети | **0** — сервис и все скрипты детерминированы |
| Кратковременно | CLI, когда агент просит таблицу (~1 с); импорт истории один раз |
| Не используется | веб-серверы, открытые порты, сторонние сервисы, телеметрия |

## Зачем отдельный вход в Telegram

`stories.py login` создаёт новую сессию **«Hermes Stories»**. Это сделано намеренно:

1. **Свой выключатель.** Сервис — единственная часть, которая может сама писать людям. Если завершить его
   сессию, отключится ровно он и больше ничего. Важно понимать, что это **не** изолирует: антиспам-ограничения
   Telegram (`PEER_FLOOD`, «можно писать только взаимным контактам») действуют на весь **аккаунт**, а не на
   одну сессию. Поэтому и нужны предохранители ниже: по умолчанию только контакты, лимиты, полная остановка
   при первом сигнале антиспама.
2. **Стоп-кран в кармане.** Telegram → Настройки → Устройства → «Hermes Stories» → «Завершить», и сервис
   мгновенно теряет доступ. Ни сервер, ни терминал не нужны.
3. **Нет конфликта ключа.** Две долгоживущие программы на одном ключе сессии работают ненадёжно, а если
   ключ одновременно используют с двух IP-адресов (VPN, прокси), Telegram его отзывает
   (`AUTH_KEY_DUPLICATED`) — и ломаются обе.
4. **Видно, что происходит.** Telegram показывает, когда сессия была активна в последний раз.
5. **Отдельный секрет.** Его можно перевыпустить, ничего больше не трогая.

Одно важно понимать: **сессий «только для чтения» в Telegram не бывает** — любая сессия даёт полный
доступ к аккаунту. Отдельный вход изолирует, но не урезает права. Поэтому строка сессии лежит только в
env-файле с правами 600 и никогда не попадает в конфиг, базу или логи. И поэтому код и облачный пароль вы
вводите сами в терминале: пароль, набранный в чате с агентом, останется в его истории и уйдёт провайдеру
модели.

## Таблицы и отчёты

| Что спросить | Что запускает агент |
|---|---|
| одна сторис, все зрители | `stories.py table story last` (или номер, или `-2`) |
| все сторис за период | `stories.py table summary --period 30d` / `--from … --to …` |
| аудитория: ядро, регулярные, новые, остывают, пропали | `stories.py table people [--status core]` |
| когда смотрят, лучший час для публикации | `stories.py table hours --period 90d` |
| сравнить сторис | `stories.py table compare 219 220 221` |
| сторис канала | `stories.py table channel --peer @channel` |
| CSV для таблицы | `stories.py export views --period 90d` |

Для каждого человека хранятся имя, фамилия, ник (все ники) и id в Telegram; смены имени и ника пишутся
в историю. В таблицах ник — кликабельная ссылка. Людей без ника видно только по имени: ссылку вида
`tg://user?id=` Telegram в сообщении бота превращает в простой текст (проверено на живом rich-сообщении),
так что она бы только выглядела кликабельной. В CSV id есть всегда.

**Родные таблицы в Telegram.** С Bot API 10.1 Telegram сам рисует Markdown-таблицы («rich messages», до
32 768 символов). В Hermes это включается так: `platforms.telegram.extra.rich_messages: true`. Без этой
настройки Hermes превращает таблицу в группы пунктов: читать можно, но не так удобно. Таблицы длиннее
`tables.max_rows` (150 строк) обрезаются, а полная версия пишется в CSV.

Ещё сервис сам, без всякой модели, присылает **пульс** через 2 часа после публикации («📈 +30% к
обычному»), **недельный дайджест** (по умолчанию в воскресенье в 20:00) и месячный. Как считаются метрики —
в [`references/metrics.md`](skills/telegram-stories/references/metrics.md).

## Автосообщения (по желанию)

![Жизнь правила — shadow, превью, подтверждённая активация — и проверки перед каждым сообщением](docs/autoresponder.ru.png)

По умолчанию выключены (`autoresponder.enabled: false`). Правило — это *какие сторис × кто × на что
реагируем × что делаем × лимиты*: «всем, кто посмотрит мою следующую сторис», «только @alex», «тем, кто
поставил ❤», «моему ядру». Новое правило сначала работает **вхолостую (shadow)**: записывает, кому ушло
бы сообщение, и ничего не отправляет. Включить его можно только с дайджестом из `rule preview`, поэтому
работает ровно то, что вы видели. Есть предохранители, которые ни одно правило не отключит:

- по умолчанию пишем только контактам, а `dialog` и `all` нужно указать явно;
- никогда не пишем ботам и тем, кто берёт звёзды за сообщения;
- одному человеку — одно сообщение на правило;
- между автосообщениями одному человеку — 7 дней;
- лимиты в день и в час, тихие часы;
- полная остановка по сигналу антиспама Telegram.

`stories.py stop` останавливает всё сразу. Формат правил и логика лимитов — в
[`references/rules.md`](skills/telegram-stories/references/rules.md).

## Ограничения Telegram

Кто смотрел сторис канала, Telegram не показывает никому: доступны только счётчики, реакции и публичные
репосты. Без Premium список зрителей пропадает через сутки после того, как сторис истекла. Зрители в
режиме инкогнито в список не попадают. Подробно — в
[`references/telegram-limits.md`](skills/telegram-stories/references/telegram-limits.md).

## Что и где хранится

| Путь | Что |
|---|---|
| `~/.hermes/telegram-stories.json` | конфиг (без секретов) |
| `~/.hermes/.env` | `STORIES_SESSION_STRING` (и id/hash API, если их не было), права 600 |
| `~/.hermes/data/telegram-stories/stories.db` | сторис, зрители со временем и реакциями, профили, правила, отправленные сообщения |
| `~/.hermes/data/telegram-stories/thumbs/` | маленькие превью сторис (`backfill --no-thumbs` — без них) |
| `~/.hermes/data/telegram-stories/exports/` | CSV, которые вы просили |

**Как посмотреть цифры.** Проще всего — спросить агента своими словами, он сам запустит нужную таблицу.
Самому на сервере: `stories.py table …` печатает те же таблицы, а `stories.py export views|people|stories
[--period 90d]` пишет CSV. Файл сохраняется в UTF-8 с BOM, поэтому Excel открывает его без кракозябр. Для
русского Excel поставьте в конфиге `tables.csv_delimiter: ";"`. Ещё можно открыть `stories.db` на чтение
в любом просмотрщике SQLite (DB Browser for SQLite, Datasette). Основные таблицы базы: `stories`, `views`,
`people`, `people_history`, `story_replies`, `rules`, `deliveries`.

Это личные данные людей, которые вас смотрят. Они остаются на вашей машине: наружу ничего не уходит, кроме
запросов к самому Telegram и уведомлений в ваш собственный чат. Тексты ответов на сторис не хранятся —
только факт ответа. Пути меняются переменными `HERMES_HOME`, `STORIES_HOME`, `STORIES_CONFIG`.

## Настройки

`~/.hermes/telegram-stories.json` — установщик создаёт его из
[`examples/config.example.json`](skills/telegram-stories/examples/config.example.json). Обычно меняют:

- `timezone`;
- `locale` (`en` или `ru` — язык заголовков таблиц);
- `channels`;
- `notify` (`auto` — бот агента и его домашний чат, `saved` — «Избранное», `none` — не присылать);
- время дайджеста;
- всё в разделе `autoresponder`.

## Удаление

`install.py --uninstall` останавливает и удаляет сервис (`--purge` удаляет ещё и собранные данные).
Потом завершите сессию «Hermes Stories» в Telegram → Настройки → Устройства и уберите
`STORIES_SESSION_STRING` из env-файла.

## Модель угроз — честно

Агент с доступом к командной строке технически может всё то же, что и сервис. Предохранители защищают от
ошибок и от чужих инструкций в тексте, который агент прочитал: правило меняется только через превью,
которое видел владелец. От злонамеренного агента они не защищают. Последняя линия обороны — лимиты, охват
«только контакты» по умолчанию, стоп-кран и отдельная сессия, которую можно завершить с телефона.

## Раскрытие (Disclosure)

- **Сеть:** Telegram MTProto (сессия сервиса); Telegram Bot API `api.telegram.org` для уведомлений, если
  задан токен бота. Больше ничего.
- **Какие файлы пишет:** пути из таблицы выше; systemd-юнит пользователя
  `~/.config/systemd/user/telegram-stories.service`; env-файл (один или три ключа).
- **Процессы:** один постоянный сервис; CLI по запросу. `install.py` запускает
  `pip install --upgrade "telethon>=1.40,<2" "qrcode>=7,<9"`, только если этих пакетов нет (`--no-deps` — не ставить).
- **Что может:** читает ваши сторис, их зрителей, реакции и ответы; пишет в личку только по активным
  правилам и в пределах лимитов; никогда не публикует, не вступает в чаты и ничего не оплачивает.
- **Нейросеть:** нет.
- **Автообновления:** нет.
